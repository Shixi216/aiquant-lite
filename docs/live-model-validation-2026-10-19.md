## 真实样本与时间边界

公告为贵州茅台控股股东增持股份计划的 **2025 年历史材料**，公告 ID `1224628637`，原文日期 2025-08-30。两条核验围绕发布主体和增持计划主题；计划不被当成已经完成的事实。来源见 [巨潮公告](http://www.cninfo.com.cn/new/disclosure/detail?stockCode=600519&announcementId=1224628637&orgId=gssh0600519&announcementTime=2025-08-30)。

个股报告通过现有 Router 生成，使用 `no_fetch=true / no_ai=true / stale_ok=true`，只读取已有本地市场数据和缓存：行情基准 2026-10-16、财报期 2026-06-30。报告响应 `order_created=false`。随后将报告中的研究材料交给新构建的 Qwen 综合角色，进行新的模型调用，再由 DeepSeek Pro 复核。

因此，本次“报告生成”“缓存情绪”“新 Qwen 综合调用”分别记录；不能声称情绪 AI、数据采集或全部提取器在本次都重新运行过。

## 为什么风险复核有实际作用

Qwen 的研究摘要仍出现两处值得修正的内容：将静态 DIF / DEA 关系写成上穿事件；将保留量价信息的资金维度标为完全缺失。DeepSeek Pro 在独立复核中指出了它们，要求使用静态描述、把资金维度标为 `PARTIAL`，并继续检查财报期与缓存新鲜度。

这是具体的审查结果，不是模型准确率指标。`completed` 表示复核执行完成；`revise` 表示研究仍待修正。系统返回原始研究与独立复核意见，未自动重写原文，人工审核也未被替代。

## 初次失败与本次修复

| 发现 | 原因 / 处理 | 最终核查 |
|---|---|---|
| 公告入口起初连接失败 | Data Hub 代理未运行；启动项目自己的代理服务，数据库仍由原 Router 持有 | 代理健康、专用公告流水线通过 |
| 公告查询后无法按 ID 解析 | 最初只读查询使用 `persist=false`；精确核验要求已有已核验官方记录 | 通过 Router 持久化选定日期的 2 条公开公告元数据，再定位 PDF |
| 研究证券代码不一致 | Handler 原先未把请求字段中的完整代码传给模型，首次返回 `600519` 而请求为 `600519.SH`，正确被校验器拒绝 | Handler 显式传递完整代码；新构建首次综合调用校验通过 |
| 摘要污染为旧 60/40 权重 | 默认研究 Prompt 写死旧权重，初次摘要同时出现四维结果与旧权重描述 | 改为只引用输入的评分来源与权重；新结果没有注入旧权重 |
| Pro 追加复核输出被截断 | premium 请求仍被固定限制 1024 Token，实际 `finish_reason=length` | 改为所选预算的单次输出上限；新调用以 8192 上限完成，审计记录 4811 个输出 Token |
| MiMo 无有效结果 | 实际 HTTP 402；不推断账户余额或具体计费原因 | 保留失败；不改成“视觉能力已启用” |

Token 用量按接口 / 审计记录呈现；输出 Token 可能含推理消耗，不能当作最终文字长度或精确费用。
