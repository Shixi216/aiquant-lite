# Router 0.9.0 stage 2: reclassify non-live APIs

Router 0.9.0 separates decision support, simulations, and reviews at the URL level. This is an API
classification change only: canonical and deprecated routes call the same services and retain the
same response models.

## Route mapping

| Canonical route | Deprecated compatibility route |
|---|---|
| `POST /v1/decisions/from-data` | `POST /v1/trading/decisions/from-data` |
| `POST /v1/simulations/backtests` | `POST /v1/trading/backtests` |
| `POST /v1/simulations/portfolio/optimize` | `POST /v1/trading/portfolio/optimize` |
| `POST /v1/simulations/paper-orders` | `POST /v1/trading/paper/orders` |
| `GET /v1/simulations/paper-account` | `GET /v1/trading/paper/account` |
| `POST /v1/simulations/protective-exits` | `POST /v1/trading/paper/protective-exits` |
| `POST /v1/simulations/kill-switch` | `POST /v1/trading/paper/kill-switch` |
| `GET /v1/reviews/daily/{date}` | `GET /v1/trading/reviews/daily/{review_date}` |
| `GET /v1/reviews/daily/{date}/markdown` | `GET /v1/trading/reviews/daily/{review_date}/markdown` |

`POST /v1/reviews/daily` is new and accepts `{"date": "YYYY-MM-DD"}`. The legacy direct-input
`POST /v1/trading/decisions` route remains available for one version because its request shape
cannot be treated as an alias of the Data Hub-backed canonical route. It is deprecated and calls
the same `DecisionService` used by the canonical decision endpoint.

## Compatibility policy

Every `/v1/trading/*` operation is marked `deprecated: true` in OpenAPI and returns:

```text
Deprecation: true
Sunset: Thu, 31 Dec 2026 23:59:59 GMT
```

The aliases are planned for removal in the next Router minor version after the sunset date.
No live-execution or broker route is reintroduced.

## Service ownership

- `DecisionService`: immutable verified-data decisions and legacy direct-input decisions;
- `SimulationService`: backtests, optimization, local Paper Trading, protective exits, and the
  Paper Trading kill switch;
- `ReviewService`: structured and Markdown daily reviews.

The Hermes-facing `scripts/generate_daily_review.py` entry point now uses `ReviewService`. No
Python package directory, decision data model, or DuckDB ledger structure changed in this stage.
