# Router 0.9.0 阶段 5：人工持仓风险复核与统一每日复盘

> 完成日期：2026-07-27

## 变更目的

阶段 5 在阶段 4 的人工成交事实账本之上增加两个分析层：

1. 针对动态人工持仓追加可追溯的风险复核；
2. 通过只读 Repository 生成跨决策、模拟和人工事实的统一每日复盘。

本阶段没有修改 `manual_trades`、人工持仓聚合逻辑或 Paper Trading 账本，也没有引入任何真实
券商或自动下单能力。

## 新增接口

- `POST /v1/manual-positions/{position_id}/risk-reviews`
- `GET /v1/manual-positions/{position_id}/risk-reviews`
- `GET /v1/manual-positions/{position_id}/risk-reviews/latest`

现有每日复盘接口保持不变：

- `POST /v1/reviews/daily`
- `GET /v1/reviews/daily/{date}`
- `GET /v1/reviews/daily/{date}/markdown`

## 风险复核流程

1. 从人工成交账本动态计算持仓投影；
2. 从持仓成交历史读取最新关联的不可变 `DecisionPacket`；
3. 刷新实时行情、公告、新闻和财务报表；
4. 重新读取 DuckDB 中实际持久化的研究记录，保证证据 ID 可追溯；
5. 执行确定性风险规则；
6. 仅在高风险且请求允许时调用 `risk_controller`；
7. 向 `manual_position_risk_reviews` 追加一条审计记录。

风险复核不会修改原成交、持仓投影或模拟账户。研究数据刷新失败、证据缺失或模型不可用都会
明确进入 `missing_information`，并在需要时降级为人工复核。

## 建议安全枚举

`recommended_action` 仅允许：

- `CONTINUE_OBSERVATION`
- `HUMAN_REVIEW_REQUIRED`
- `CONSIDER_REDUCING`
- `CONSIDER_EXITING`

这些结果是建议，不是可执行指令。风险复核响应不包含订单对象，也不存在自动减仓路径。

## 统一每日复盘

`ReviewService` 只接收四个能力受限的只读 Repository：

- `DecisionReadRepository`
- `SimulationReadRepository`
- `ManualTradeReadRepository`
- `ManualPositionRiskReviewReadRepository`

它可以比较当时决策包、模拟结果、用户人工成交、当前人工持仓、风险规则、计划偏离、模型问题、
证据缺失和数据质量问题。它不能创建模拟成交或人工成交，不能修改持仓，不能确认成交 preview，
也不能调用任何外部交易程序。

## 数据与审计

`manual_position_risk_reviews` 是追加式审计表。记录包含复核时间、数据截止时间、风险等级、
原始逻辑状态、规则触发、已验证新事实、模型推断、缺失信息、证据记录 ID、模型调用 ID 和安全
建议枚举。Repository 没有更新或删除方法。

## 验证

阶段 5 增加了风险复核隔离、模拟账户隔离、安全枚举、数据截止时间、证据追溯、无订单对象、
无自动减仓路径、只读复盘依赖和三条新 API 的测试。`check_no_live_execution.py` 增加阶段 5
