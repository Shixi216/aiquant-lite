# Router 0.9.0 stage 3: immutable DecisionPacket

Stage 3 replaces mutable decision traces at the decision API boundary with append-only,
source-traceable `DecisionPacket` versions. It changes decision models, decision persistence,
decision queries, and adversarial review only. Simulation account and order ledgers are unchanged.

## Version and integrity rules

- `(decision_id, decision_version)` is the `decision_packets` primary key.
- Status is `DRAFT`, `FINAL`, or `SUPERSEDED`.
- A `FINAL` packet cannot be overwritten. New data or reanalysis inserts the next version and
  records `supersedes_version`.
- Superseding changes only the old version's lifecycle status and corresponding integrity hash;
  its core payload, cutoff time, evidence, model output, and risk conclusion remain unchanged.
- `packet_hash` is SHA-256 over canonical JSON with `packet_hash` excluded.
- Every repository read recomputes the hash and validates normalized evidence, opinions, risk
  vetoes, and initial adversarial-review snapshots.
- An integrity mismatch fails the read and writes `decision_integrity_audit`.
- Every `source_record_id` must exist in the Data Hub record store. Every supplied
  `model_call_id` must exist in the model-call audit store.
- Verified facts and model inferences use distinct typed structures and cannot be substituted for
  one another.

## Persistence

Stage 3 adds these decision-owned DuckDB tables:

- `decision_packets`
- `decision_evidence`
- `agent_opinions`
- `risk_vetoes`
- `adversarial_reviews`
- `decision_integrity_audit`

The existing Paper Trading account, position, order, fill, approval, and event tables are not
modified.

## API

| Method and route | Purpose |
|---|---|
| `POST /v1/decisions/from-data` | Generate and persist a version 1 packet from traced Data Hub records |
| `GET /v1/decisions/{decision_id}` | Read and verify the latest version |
| `GET /v1/decisions/{decision_id}/versions` | List and verify all versions |
| `GET /v1/decisions/{decision_id}/versions/{version}` | Read and verify one version |
| `POST /v1/decisions/{decision_id}/challenge` | Append an adversarial review |

A challenge never edits an existing packet. By default it stores only a new adversarial-review
record. If `create_new_version` is explicitly true, it also inserts a new packet version with a
fresh cutoff time, source list, model-call list, and hash, then marks the preceding `FINAL` version
as `SUPERSEDED`.

Risk review remains advisory. It cannot create a Paper Trading order or call any current or future
execution repository. `DecisionService` accepts only `DecisionRepository`.
