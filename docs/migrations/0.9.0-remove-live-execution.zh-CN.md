# Router 0.9.0：移除真实券商与自动下单能力

## 变更结论

Router 0.9.0 已从生产代码、配置和 OpenAPI 中彻底删除真实券商连接与自动下单能力。项目现在
只支持研究、回测和本地 Paper Trading；研究决策不存在通往真实订单的代码路径。

## 历史背景

0.8.1 曾包含一组锁死的安全占位设计：通用 `BrokerAdapter` 抽象、始终拒绝执行的
`DisabledLiveBroker`、不连接客户端的中信 QMT/xtquant 占位器、券商能力目录，以及始终返回
HTTP 423 的实盘订单路由。占位器没有安装或导入 xtquant，也不读取账户、密码、Cookie 或
交易凭据，但这些接口仍可能让使用者误以为仓库准备接入真实账户。

0.9.0 不再保留兼容占位器。以下生产文件已删除：

- `trading/broker.py`
- `trading/adapter_registry.py`
- `trading/adapters/__init__.py`
- `trading/adapters/qmt_xtquant.py`

以下 OpenAPI 路由已删除，不保留 HTTP 423 兼容响应：

- `GET /v1/trading/brokers`
- `POST /v1/trading/live/orders`

环境配置中的 `OPC_LIVE_TRADING_ENABLED` 也已删除。仓库不接受 `BROKER_ACCOUNT`、
`BROKER_PASSWORD`、`TRADING_PASSWORD`、`QMT_PATH`、`XTQUANT_TOKEN` 或券商 Cookie。

## 仍然保留的能力

- Data Hub 与六个只读 Finance Data MCP 工具
- Agent Router 与多模型路由
- 技术面、基本面、策略生成、风险否决和对抗审查
- 回测、组合优化、本地 Paper Trading、模拟仓位与模拟止损止盈
- DuckDB 审计与每日结构化复盘

Paper Trading 继续使用原有 `/v1/trading/paper/*` API 和 DuckDB 账本结构。本次迁移没有新增
人工成交模块、没有迁移 Python 包目录，也没有修改数据库账本结构。

阶段 2 已将正式 Paper Trading API 重新分类到 `/v1/simulations/*`；上述旧路径仅保留为一版
带弃用响应头的兼容别名，账本结构仍未改变。

## 安全回归检查

`scripts/check_no_live_execution.py` 会检查依赖、生产源码导入、配置、实际 FastAPI OpenAPI、
Finance Data MCP 工具注册表和间接桌面/客户端控制路径。对应的测试位于
`tests/test_no_live_execution.py`。
