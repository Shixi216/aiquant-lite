## 为什么这样设计

迅投官方文档将交易流程拆成启动交易线程、连接 MiniQMT、订阅账号、查询资产/持仓/委托/成交、
提交委托、撤单和接收回调。连接断开后还需要主动重新连接。参见：

- [XtQuant 交易模块](https://dict.thinktrader.net/nativeApi/xttrader.html)
- [XtQuant 快速开始](https://dict.thinktrader.net/nativeApi/start_now.html)
- [XtQuant 完整实例](https://dict.thinktrader.net/nativeApi/code_examples.html?id=7zqjlm)
- [XtQuant 常见问题](https://dict.thinktrader.net/nativeApi/question_function.html?id=TB5IbM)

因此通用 `BrokerAdapter` 先定义以下与券商无关的边界：

- 能力和可用状态；
- 账户快照；
- 委托查询；
- 委托提交；
- 撤单。

QMT 占位适配器另外列出未来要实现的连接订阅、持仓、成交、回调、重连和对账能力，但没有对应
执行代码。以后真正实现时，xtquant 对象只能存在于独立适配器进程中，不能进入 Agent、模型
Prompt、Hermes 消息通道或通用数据服务。

## 向中信证券确认的问题

请只向券商确认权限和产品信息，不要把密码发给本项目或任何聊天窗口：

1. 当前普通个人 A 股账户是否支持迅投 QMT 或 MiniQMT？
2. 是否需要单独申请、签署协议、满足资产或交易经验门槛？
3. 是否开放 xtquant Python 交易 API，还是仅开放行情/研究接口？
4. 是否提供与真实资金隔离的模拟交易环境？模拟委托是否覆盖查询、撤单和成交回报？
5. 中信提供的客户端名称、官方下载渠道和支持的 Python 版本是什么？
6. 是否允许外部 Python 进程连接，是否限制同时连接数、机器或网络环境？
7. 普通股票账户的账号类型、支持市场和委托类型有哪些？
8. 是否有正式接口文档、错误码、交易时间、频率限制和技术支持渠道？

请保留券商回复的产品名称、文档版本和权限结论即可；不要保存账号、密码、交易密码、Cookie、
令牌、二维码截图或客户端登录文件。

## 权限确认后的实施顺序

即使券商确认支持，也不会直接接真实账户。后续必须按顺序进行：

1. 人工核对官方安装包与文档来源；
2. 在 E 盘建立隔离的 QMT 沙箱目录；
3. 只连接券商提供的模拟环境；
4. 先实现只读健康检查、资产、持仓、委托和成交查询；
5. 验证断线重连、回调去重、时钟和对账；
6. 在模拟环境测试限额、幂等、撤单和紧急停止；
7. 连续运行至少 30 个交易日并形成验收报告；
8. 经人工审批后，另行评审是否有必要设计真实适配器。

在第 8 步完成前，`OPC_LIVE_TRADING_ENABLED=false` 和 QMT 占位适配器的强制拒绝行为不得改变。
