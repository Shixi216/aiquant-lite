# 模型、数据库与日志排障复盘

**研究系统的可靠性，需要落到真实请求、数据库边界和可核对的失败记录。** 近期排障把下面几类问题转为公开实现与回归；此页只保留通用方法，不发布个人调用明细。

| 故障形态 | 审核方法 | 已公开的治理方式 |
|---|---|---|
| 任务列表与实际模型调用数不一致 | 从物理调用表核对时间窗，包含空 `task_id` 与悬空关联 | 调用审计覆盖独立研究；区分返回行数、完整时间窗统计和未关联数量 |
| 模型返回空内容或被截断 | 分开检查网络、完成预算、结束原因与结构校验 | 自动化研究任务增加完成预算；失败保留已知用量与结束原因，不把推理文本当最终答案 |
| 本机直连超时，配置代理可用 | 分别核对连接路径与已有代理 / `NO_PROXY` 设置 | 多个模型客户端遵守环境代理配置 |
| 主库短暂争用被当成业务异常 | 区分 Owner 占用、锁等待耗尽与普通业务错误 | 主 DuckDB 保持单 Owner；明确竞争错误返回 503 与 `Retry-After` |
| 日志故障掩盖原异常 | 核对原请求异常与日志写入异常 | 性能日志增加时间与失败分类；日志不可写时保留业务错误 |
| 宿主时区改变历史判断 | 用不同 SQL 会话时区复核同一截止日 | A 股业务日显式锚定 `Asia/Shanghai` |

## 审计如何保持诚实

已留存调用数量不自动等于完整请求总量；审计落库失败必须单独披露。错误展示脱敏，保留旧记录。无时间戳的旧日志不能用文件修改时间“还原”每次请求日期。

公开提交 `53022f7` 的 [Windows CI](https://github.com/Shixi216/aiquant-lite/actions/runs/39104295548) 记录后端 **1794 passed、0 failed、4 skipped、8 deselected**，前端 **5 passed**、构建成功。这是该源码提交的软件验证，不能替代真实行情质量、完整调用审计或策略绩效验证。
