# 四、数据状态标准

废除“永远最新数据”这种不准确表述。

统一使用以下状态：

## FRESH

数据新鲜、覆盖完整，可以正常给出交易建议。

## DEGRADED

部分非核心数据缺失，可以继续分析，但必须：

- 降低置信度
- 标记缺失字段
- 说明缺失对结论的影响
- 不得把缺失数据当成正常数据

## STALE

核心行情数据陈旧。

必须：

- 停止扫描推荐
- 不输出建仓或买入建议
- 触发后台刷新
- 返回数据陈旧状态

## FAILED

核心数据获取失败或无法确定时间有效性。

必须停止正式决策。

- income

- margin_detail
- top_list

## 腾讯源：盘中行情补充

用于：

- 盘中或接近实时价格
- 涨跌幅
- 成交量
- 临时行情校验
- Tushare盘后数据尚未生成时的行情补充

腾讯源不能覆盖或替换Tushare历史主数据。

## AKShare

用于：

- 东方财富新闻
- 盘中行情备用
- 数据源降级补充

必须记录其实际上游来源。

## BaoStock

用于：

- 历史日线校验
- Tushare失败时备用
- 数据一致性检测

不作为实时快照主源。

## 巨潮资讯

作为上市公司公告主要来源。

## 政府及监管官方网站

作为政策文件主要来源，包括白名单中的政府、监管机构和交易所网站。

## Tavily

只作为：

- 实时新闻证据补全
- 官方来源检索
- 多来源交叉验证
- 旧闻识别
- 重大事件补充

Tavily不能直接生成情绪分，也不能把搜索结果数量作为关注度分数。

# 十、五维因子的正式使用边界

情绪面、政策面和资金面目前继续作为增强层，不直接替换60/40正式核心。

允许它们影响：

- 置信度
- 建仓比例
- 建仓节奏
- 加仓节奏
- 持有周期
- 风险等级
- 止损宽度
- 是否等待确认
- 是否触发风险VETO

当前结构：

## 正式方向

由技术面60% + 基本面40%确定。

## 情绪面

用于判断：

- 事件利好或利空
- 市场关注度
- 短期交易拥挤度
- 短期催化强弱
- 反转风险

## 政策面

用于判断：

- 政策支持
- 行业限制
- 监管风险
- 重大公告风险
- 退市、立案、处罚等风险

重大政策或监管风险允许触发硬VETO。

## 资金面

用于判断：

- 是否适合立即建仓
- 是否适合追涨
- 是否适合分批买入
- 是否出现资金撤离
- 是否需要减仓

五维影子评分继续保存，用于后续回测验证：

- 技术45%
- 基本30%
- 情绪15%
- 政策5%
- 资金5%

正式输出必须同时显示：

- 正式60/40评分
- 五维增强观察结果
- 两者是否一致
- 不一致原因

不得把未经验证的五维影子结果伪装成已验证正式策略。

# 十一、硬风险VETO

硬VETO优先级高于任何买入信号。

至少包括：

- 退市风险
- 重大违法
- 证监会立案
- 财务造假
- 审计非标准意见
- 资金链断裂
- 大额债务违约
- 控股股东重大风险
- 核心资产被冻结
- 长期停牌风险
- 连续经营重大不确定性
- 数据严重缺失
- 数据时间无法确认
- 流动性不足
- 极端价格异常
- 无法验证的重大利空事件

VETO输出必须包括：

- veto_triggered
- veto_type
- veto_reason
- evidence_source
- evidence_time
- confidence
- action_override

VETO触发后的动作：

未持仓：

- 回避
- 禁止建仓
- 等待风险解除

已持仓：

- 减仓
- 清仓
- 等待核验

系统不得只输出“风险较高”，必须给出明确行动。

# 十二、明确动作体系

统一动作枚举，所有输出使用中文，并同时保留内部英文枚举。

## 未持仓动作

- STRONG_BUY：强烈建仓
- BUY：建仓
- SMALL_BUY：小仓试错
- WAIT：等待
- AVOID：回避

## 已持仓动作

- ADD：加仓
- HOLD：持有
- REDUCE：减仓
- TAKE_PROFIT：止盈
- STOP_LOSS：止损
- EXIT：清仓

不得使用模糊表达：

- 可以关注
- 值得留意
- 后续观察
- 自行判断

除非动作本身确实为WAIT。

# 十三、动作生成规则

所有动作阈值必须配置化、版本化，不得散落在代码中。

初始默认映射可采用：

## 无持仓

- formal_score ≥ 0.65，置信度≥0.70，无VETO：
强烈建仓或建仓
- formal_score 0.40至0.65，置信度≥0.60：
小仓试错或分批建仓
- formal_score -0.20至0.40：
等待
- formal_score < -0.20：
回避

## 已持仓

- formal_score ≥0.65，趋势与资金确认：
持有或加仓
- formal_score 0.20至0.65：
持有
- formal_score -0.20至0.20：
减仓观察或持有，不新增仓位
- formal_score -0.50至-0.20：
减仓
- formal_score ≤-0.50：
清仓或止损

## 低置信度限制

confidence < 0.55时：

- 不得输出强烈建仓
- 不得输出满仓
- 不得输出确定性清仓，除非VETO触发
- 输出小仓、等待或核验

## 数据状态限制

- FRESH：正常决策
- DEGRADED：降低仓位和置信度
- STALE：停止推荐
- FAILED：停止决策

# 十七、持仓诊断

用户存在人工持仓或Paper持仓时，分析必须结合：

- 持仓数量
- 平均成本
- 当前价格
- 浮动盈亏
- 持仓比例
- 持仓时间
- 剩余现金
- 组合相关性
- 行业集中度

相同股票针对不同用户可以得出不同动作。

例如：

- 未持仓用户：等待建仓
- 低成本持仓用户：继续持有
- 高位重仓用户：减仓
- 已严重亏损用户：禁止盲目补仓，按风险重新评估

不得只根据股票评分输出统一动作。

# 十八、人工持仓和Paper账户

## 人工持仓

用户可以通过企业微信或QQ输入：

- 我买了某股票100股，价格10元
- 我卖了某股票50股，价格12元
- 我清仓了某股票
- 修改成本为某价格

系统必须：

- 识别股票
- 解析数量和价格
- 展示待记录内容
- 用户确认后写入人工成交账本
- 更新持仓成本和数量
- 保存审计记录

用户明确说“记录我已经买入”时，可视为确认。

## Paper账户

允许系统：

- 创建模拟账户
- 模拟建仓
- 模拟加仓
- 模拟减仓
- 模拟清仓
- 模拟止损
- 计算手续费、收益、回撤和持仓

# 二十、企业微信和QQ对话行为

对话入口必须直接给出明确结论。

示例：

> 当前建议：小仓分批建仓。
> 建议初始仓位：5%。 建仓区间：13.20至13.60元。 加仓条件：放量站稳14.10元且资金面未恶化。 止损条件：收盘跌破12.70元或重大风险公告出现。 第一目标区间：14.80至15.50元。 预期周期：2至8周。 正式评分：+0.60。 置信度：0.72。 主要原因：技术趋势偏强、基本面为正、当前无硬VETO。 主要风险：短期涨幅较大、板块波动。
> 是否创建交易计划？


用户：

> 我已经持有20%，成本15元。


系统必须重新按用户持仓计算，不能继续给出同样的建仓建议。
